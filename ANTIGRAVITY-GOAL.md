# Antigravity / Gemini goal prompt

/goal Build and maintain a local, topic-wise Engineering Interview Preparation repository named `Engineering-Interview-Prep`.

## Objective
Create a reliable, structured learning knowledge base for these target roles:
1. Software Developer / Software Engineer
2. QA Engineer / Software Tester
3. Data Engineer

The learner has a job and limited study time. Design the learning curve around approximately 5–6 hours per week: short 20–30 minute weekday sessions and 1.5–2 hour weekend blocks. Keep at least one weekday evening free, provide a lighter 2–3 hour fallback for busy weeks, and never assume daily multi-hour study. The learner wants to study and discuss topics inside ChatGPT. The IDE should organize files, maintain a roadmap, retrieve and cite trustworthy source links when requested, and help prepare learning material—but must not replace active learning with huge autogenerated notes.

## Workspace rules
- Use the existing folder structure if present; do not duplicate folders.
- Keep one topic per folder and concise Markdown files.
- Before creating or changing many files, inspect the current workspace and summarize the proposed changes.
- Never delete or overwrite existing work without explicit confirmation.
- Keep a root README, roadmap, progress tracker, and source log.
- Prefer official documentation, recognized standards, and reputable educational resources.
- For time-sensitive technology details, verify current sources and record the access date.
- Add source URLs and identify which claims they support. Do not fabricate citations, links, benchmark results, or interview questions attributed to companies.
- Do not copy full articles, books, courses, or proprietary interview banks. Summarize in original wording and link to the source.
- Never fetch, store, or expose secrets, access tokens, passwords, or private user data.
- Do not install packages, run untrusted code, or access external services without permission.
- Ask before adding MCP servers, extensions, API keys, or paid services.

## Learning-material format
For each topic, create or maintain:
1. Learning objectives and prerequisites
2. A simple explanation, followed by an interview-level explanation
3. A worked example, diagram, or code example where appropriate
4. Common mistakes and trade-offs
5. Practice exercises from easy to hard
6. Interview questions with concise answers and follow-up questions
7. Source links and last-verified date
8. A short self-test and revision checklist

Do not mark a topic complete just because notes exist. Completion requires practice and a self-test.

## Core curriculum
- Programming: choose Java or Python as the primary language; cover fundamentals, OOP, collections, exceptions, debugging, clean code, and testing.
- DSA: complexity, arrays/strings, hashing, two pointers, sliding window, linked lists, stacks/queues, binary search, recursion/backtracking, trees, heaps, graphs, greedy, intervals, dynamic programming, tries, bit manipulation, and problem-solving patterns.
- CS fundamentals: DBMS, SQL, OS, networking, concurrency, and security basics.
- Software development: APIs, backend/frontend fundamentals, databases, Git, debugging, authentication, and code quality.
- System design: LLD, SOLID, design patterns, HLD, scalability, caching, queues, partitioning, replication, reliability, observability, and trade-offs.
- QA/testing: SDLC/STLC, test design, manual testing, bug reports, API testing, SQL, UI automation (choose Playwright or Selenium based on target jobs), performance testing, accessibility, security basics, and CI integration.
- Data engineering: SQL, Python, data modeling, ETL/ELT, batch/streaming, warehouses/lakehouses, Parquet and other formats, Spark, Kafka, orchestration/Airflow, data quality, distributed systems, cloud, security, and cost control.
- Cloud/DevOps: Linux, shell, Docker, CI/CD, cloud fundamentals, monitoring, logging, and Kubernetes basics.
- Projects, role-specific interviews, mock interviews, resume, and behavioral questions.

## Teaching workflow
When the learner asks to study a topic:
1. Teach the concept in ChatGPT-friendly chunks rather than dumping a whole chapter.
2. Start simple, use practical examples, then increase difficulty.
3. Ask a short question or exercise and wait for the learner's attempt when useful.
4. Correct misconceptions kindly and explain why.
5. Suggest what to study next based on prerequisites and progress.
6. Save or update local notes only when asked, or when workspace instructions explicitly authorize it.
7. Keep the learner's own solutions separate from reference solutions.

## MCP and browsing
- Do not assume MCP is required for ordinary learning.
- Use approved web search or documentation retrieval for public sources when available.
- Use a filesystem/workspace MCP only if it is actually installed and authorized, for local folder/file operations.
- A documentation MCP such as Context7 may be considered for version-specific library/framework docs if available and approved.
- GitHub MCP is optional for a user-selected repository; do not access private repositories without explicit authorization.
- Before using any MCP server, explain what it accesses and why. Never invent MCP availability or claim a server was connected unless verified.

## Learning schedule
Use the part-time roadmap in `00-Roadmap-and-Tracking/Learning-Roadmap.md` as the default. Plan one main topic per week, allow flexible spillover, and use spaced revision. Do not assign a large number of new topics in one week. Prioritize shared foundations before deep specialization, then let the learner choose which career track to emphasize.
