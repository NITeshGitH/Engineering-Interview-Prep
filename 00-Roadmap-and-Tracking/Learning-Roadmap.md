# Part-Time Learning Roadmap (Designed Around a Job)

## Guiding rule
Plan for **5–6 hours per week**, not a full-time study schedule. Consistency matters more than daily streaks. If work is tiring, use the minimum version and continue next session without doubling the workload.

## Weekly rhythm
- **Monday — 20 minutes:** revise one previous concept or flashcards.
- **Tuesday — 25 minutes:** learn one small concept.
- **Wednesday — Rest / optional 10-minute recap.**
- **Thursday — 25 minutes:** solve one small exercise or answer interview questions.
- **Friday — Rest or optional catch-up.**
- **Saturday — 2 hours:** focused learning and hands-on practice.
- **Sunday — 1.5–2 hours:** revision, self-test, and plan the next week.

Expected total: about 4.5–5.5 hours; optional time can bring it to around 6 hours. Keep at least one full evening free.

## 24-week starter roadmap

This is a flexible sequence, not a deadline. Spend extra weeks on difficult topics as needed.

### Phase 1 — Shared foundations (Weeks 1–6)
1. Choose one primary language (Java or Python); revise syntax and core collections.
2. OOP, clean code, debugging, and basic testing.
3. Big-O, arrays, strings, and hashing.
4. Two pointers, sliding window, and binary search.
5. Linked lists, stacks, queues, recursion, and basic backtracking.
6. SQL foundations, joins, grouping, keys, and constraints.

### Phase 2 — Core interview foundations (Weeks 7–12)
7. DBMS, indexes, transactions, normalization, and query thinking.
8. Trees, BSTs, traversals, and heaps.
9. Graph basics: BFS, DFS, and common representations.
10. Operating systems and concurrency basics.
11. Networking: HTTP, DNS, TCP/IP, TLS, and APIs.
12. DSA review week: solve mixed problems and explain solutions aloud.

### Phase 3 — Explore role tracks (Weeks 13–18)
13. Software development: REST APIs, Git workflow, debugging, and code quality.
14. LLD: requirements, classes, interfaces, SOLID, and one small design.
15. QA foundations: SDLC/STLC, test design, boundary values, equivalence classes, and bug reports.
16. QA practice: API testing, SQL for testers, and a small automation test.
17. Data engineering: Python for data, advanced SQL, data modeling, and ETL/ELT.
18. Data engineering practice: batch pipelines, data quality, retries, and incremental loads.

### Phase 4 — Choose and deepen (Weeks 19–24)
19. HLD basics: requirements, capacity estimates, APIs, and data stores.
20. Caching, queues, consistency, partitioning, reliability, and trade-offs.
21. Pick one target role for a deeper mini-project.
22. Build and test the project; document setup and design decisions.
23. Role-specific interview questions and a mock interview.
24. Review weak areas, update resume stories, and plan the next 12 weeks.

## If you can study only 2–3 hours in a busy week
- Do one 20-minute weekday recap.
- Do one 60–90-minute weekend session.
- Complete one small exercise.
- Move unfinished items forward; do not cram or treat it as failure.

## Topic completion criteria
Mark a topic "Interview Ready" only when you can:
- explain it without reading notes,
- solve or demonstrate a representative exercise,
- answer at least 3 interview questions,
- name common pitfalls or trade-offs.

## Weekly review
At the end of Sunday, record:
- What I learned
- What I practiced
- What I could not explain
- One priority for next week
- Confidence from 1–5
